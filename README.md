# OAuth App Readiness

Look up an app and learn what it takes to create its OAuth app and get it approved: how hard it is, how long it takes (including the wait for approval), what usually blocks it, and which steps an agent can do for you. If there's no guide yet, an agent investigates the app live and writes a shareable one.

## What I learned, and the product decisions it led to

**The registration form is not the problem.** For every provider I looked at, creating the app takes 15–30 minutes. Developers can't predict the gap between "works for me in dev" and "any user can connect": Google's verification and CASA assessment, Meta's App Review plus Business Verification, Shopify's protected customer data approval, X's paid tiers, GitHub's per-organization owner approval. Composio's existing guides (e.g. composio.dev/auth/googleapps) cover the clicks well. They give verification one line and include no time estimate.

So every guide leads with a **verdict**, not steps:
- **Tier:** *self-serve*, *review required*, or *partner-gated*.
- **Time to first connection** vs. **time to production.** These differ by days to weeks, and conflating them is how launches slip.
- **Hands-on effort** vs. **approval wait.** Engineers plan around the first, PMs around the second.

**Managed vs. bring-your-own is the first fork.** Of the 382 OAuth toolkits on Composio, 258 have no managed app (directory snapshot, 2026-10-28). Each guide says whether you can start on Composio's managed app today and what makes you switch: branding, scopes, rate limits.

**"What an agent can do vs. you" is explicit per step.** Every step is tagged *agent can do*, *agent preps, you submit*, or *you*. Anything needing your account, legal entity, payment or judgment is yours.

**Evidence is a first-class part of the guide, not a footnote.** Each factual claim is labelled *tested* (observed by a live probe or a hands-on attempt), *verified* (a second agent pass re-read the source and confirmed it), *sourced* (cited, not re-checked), or *uncertain*. Review wait times are rarely official, and a guide that presents a forum anecdote as fact is worse than no guide.

**Scope I chose not to do:** accounts and logins, editing guides in the UI, tracking a developer's progress, and filling all 100 guides. The library index already lists all 382 Composio OAuth toolkits, and any of them can be generated on demand.

## How it works

```
query ─► Research agent ──► Compose ──► Fact-check agent ──► shareable guide
         web_search            JSON           web_fetch of
         web_fetch             guide,         each cited source,
         probe_oauth           evidence       verdict per claim
         Composio lookup       rules enforced
```

- **Research** (`src/lib/agent/pipeline.ts`, `prompts.ts`): Claude Opus 5.5 with Anthropic's server-side web search and web fetch, plus two of our own tools (`probes.ts`):
  - `lookup_composio_toolkit` checks whether a managed app exists.
  - `probe_oauth` makes live read-only observations. It fetches the OIDC discovery document. It calls the authorize endpoint with a deliberately invalid client and Composio's redirect URI to confirm the endpoint is live and see how the provider rejects unknown clients. It also checks whether the app-registration portal is behind a login.

  This is the "attempt the setup" part that works without provider accounts.
- **Compose:** turns the research into the `GuideDraft` schema (`src/lib/schema.ts`), with the schema in the prompt and zod validation plus a repair retry. The schema was too large for constrained decoding.
- **Evidence rules are enforced in code** (`enforceEvidence`), not just requested:
  - The writer cannot mark anything *verified*.
  - *Tested* requires a matching probe.
  - A claim citing a URL the agent never found or opened is downgraded to *uncertain* automatically.
- **Fact-check** (`verifyGuide`): a separate pass re-opens the sources behind the highest-stakes claims first (verdict, then blockers, then prerequisites). It marks each claim *supported*, *partial*, *not found*, *contradicted* or *unreachable*, and adjusts the label.
- **Live UI:** `/generate` streams the agent's searches, page reads, probes and claim checks as NDJSON. Research and compose run in one request and fact-checking in a second, so each stays under the serverless time limit.
- **Library** guides are generated by the same pipeline (`scripts/build-library.ts`), then reviewed by a person. Corrections are recorded on the guide and shown on the page.

## Setup

```bash
npm install
cp .env.example .env.local      # add ANTHROPIC_API_KEY
npm run dev                     # http://localhost:3000
```

Generated guides are saved to `.data/guides/` locally, or to Vercel Blob when `BLOB_READ_WRITE_TOKEN` is set.

Rebuild or add library guides:

```bash
npx tsx --env-file=.env.local scripts/build-library.ts "Slack" "HubSpot"
```

Research results are cached in `.data/research/`, so a failed compose doesn't redo the research.

A live generation takes about 2–4 minutes and costs roughly $1–2 in API usage.

## Limitations

- **No real app registrations.** The agent doesn't sign in, register apps, or submit reviews. "Tested" means a public, unauthenticated probe or a person's attempt, recorded per guide.
- **Wait times are soft.** Providers rarely publish review SLAs. Most estimates are community-reported ranges and are labelled *uncertain*.
- **The fact-checker re-reads cited pages, not the web.** It catches misquotes and stale claims. It won't find a better source that the research agent missed.
- **Pages that render with JavaScript or sit behind a login** (some developer consoles) can't be read, so those claims stay *sourced* or *uncertain*.
- **Guides are a snapshot.** Each one shows its generation and fact-check dates. There is no scheduled refresh yet.
- **Abuse protection is minimal:** a per-instance rate limit plus a spend cap on the API key. A production version would need auth and a queue.
